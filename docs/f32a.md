# F32a Instruction Set Architecture (ISA) Documentation

The F32a ISA is a stack-based instruction set designed for educational purposes. This documentation provides an overview of the instructions available in the F32a ISA, their syntax, and their semantics.

## Architecture Overview

The F32a architecture is a 32-bit stack-based architecture inspired by Forth systems. It features:

- Two primary stacks: data stack and return stack
- Two general-purpose registers: A and B
- Stack-oriented operations that simplify many programming tasks
- Extended Arithmetic Mode (EAM) for carry-dependent operations
- Carry flag for arithmetic operations
- Memory-mapped I/O

This stack-based architecture offers a different programming paradigm compared to register-based architectures, making it excellent for understanding alternative computational models.

Comments in F32a assembly code are denoted by the `\` character.

Inspired by [F18a](https://www.greenarraychips.com/home/documents/greg/DB001-221113-F18a.pdf)

## ISA Specific State Views

- `A:dec`, `A:hex` -- `A` register.
- `B:dec`, `B:hex` -- `B` register.
- `T:dec`, `T:hex` -- Top of the data stack.
- `S:dec`, `S:hex` -- Second value on the data stack.
- `R:dec`, `R:hex` -- Top of the return stack.
- `stack:dec`, `stack:hex` -- Entire data stack.
- `rstack:dec`, `rstack:hex` -- Entire return stack.
- `EAM` -- Extended Arithmetic Mode (1 if enabled, 0 if disabled).
- `C` -- Carry Flag (1 if set, 0 if cleared).

### Stack utilization

The simulator tracks the high-water mark (deepest level reached) of each stack over the whole run and exposes it through two summary view variables. They are run-totals, so use them with `slice: last`.

- `f32a:data-stack-max` -- maximum data stack depth reached during execution.
- `f32a:return-stack-max` -- maximum return stack depth reached during execution.

Example -- print a stack-depth summary at the end of the simulation:

```yaml
reports:
    - name: stacks
      slice: last
      view: |
        f32a:data-stack-max:   {f32a:data-stack-max}
        f32a:return-stack-max: {f32a:return-stack-max}
```

For `factorial.s` computing `4!` the summary reads:

```text
f32a:data-stack-max:   5
f32a:return-stack-max: 3
```

The return-stack depth reflects how deeply the recursive/nested calls nested; the data-stack depth bounds how many operands were live at once -- useful for sizing the stack region and spotting runaway recursion.

Both lines are also emitted together by the generic `{isa-specific}` summary block, which lets a single report template stay uniform across ISAs.

## Instructions

Instruction size: 1 byte for opcode, 4 bytes for each argument.

Each instruction below carries a **stack effect** in the usual notation: the
mnemonic, any immediate as `<name: type>`, then `( before -- after )`
describing the data stack. The top of the stack is written rightmost, so `+ (
s: i32, t: i32 -- sum: i32 )` pops `t` from the top and `s` from under it.
Effects on the return stack and on registers `A`, `B` and `P` appear in the
description instead, since they are not data-stack traffic.

### Instruction Fetch

Instructions are fetched a memory word at a time: the 4 bytes at an address
divisible by 4 are read into the instruction register IR. An instruction whose
first byte is already in IR costs no read, so up to four 1-byte instructions
share one. An instruction that continues past IR (a 5-byte one always does)
reads the next word, which replaces IR. A jump reads the target's word unless
IR already holds it. So `mem:reads` and `mem:per-instruction` show 0, 1 or 2
reads for a fetch. `swap` from `example/f32a/factorial.s` costs 2 reads for its
7 instructions:

```text
Address  Exec  Read  Write  Instruction
0x01c       9     1      0  Over @swap
0x01d       9     0      0  TIntoR
0x01e       9     0      0  TIntoR
0x01f       9     0      0  Drop
0x020       9     1      0  RIntoT
0x021       9     0      0  RIntoT
0x022       9     0      0  Return
```

### Extended Arithmetic Mode (EAM)

Extended Arithmetic Mode (EAM) is a mode that allows us to add with carry bit. See details in `add` instruction.

### Carry Flag

Most of the instructions drop (clear) the carry flag. Specifically, any instruction that pushes to the data stack clears the carry flag as a side effect. Exceptions: `add` (sets carry flag based on overflow), `dup` (preserves carry flag).

### Data Movement Instructions

- **Literal**
    - **Syntax:** `<value>` or `lit <value>`
    - **Stack effect:** `lit <value: i32> ( -- value: i32 )`
    - **Description:** Push an immediate value onto the data stack. The `lit` keyword is optional — a bare number, hex value (`0xFF`), or character literal (`'A'`) is sufficient.

- **Fetch from Address**
    - **Syntax:** `@p <address>`
    - **Stack effect:** `@p <address: i32> ( -- value: i32 )`
    - **Description:** Push the value from a specific address onto the data stack.

- **Fetch**
    - **Syntax:** `@`
    - **Stack effect:** `@ ( -- value: i32 )`
    - **Description:** Push the value from the address in register A onto the data stack.

- **Fetch Plus**
    - **Syntax:** `@+`
    - **Stack effect:** `@+ ( -- value: i32 )`
    - **Description:** Push the value from the address in register A onto the data stack and increment A.

- **Fetch B**
    - **Syntax:** `@b`
    - **Stack effect:** `@b ( -- value: i32 )`
    - **Description:** Push the value from the address in register B onto the data stack.

- **Store to Address**
    - **Syntax:** `!p <address>`
    - **Stack effect:** `!p <address: i32> ( value: i32 -- )`
    - **Description:** Store the top value of the data stack into a specific address.

- **Store**
    - **Syntax:** `!`
    - **Stack effect:** `! ( value: i32 -- )`
    - **Description:** Store the top value of the data stack into the address in register A.

- **Store Plus**
    - **Syntax:** `!+`
    - **Stack effect:** `!+ ( value: i32 -- )`
    - **Description:** Store the top value of the data stack into the address in register A and increment A.

- **Store B**
    - **Syntax:** `!b`
    - **Stack effect:** `!b ( value: i32 -- )`
    - **Description:** Store the top value of the data stack into the address in register B.

- **A-Store**
    - **Syntax:** `a!`
    - **Stack effect:** `a! ( value: i32 -- )`
    - **Description:** Store the top value of the data stack into register A.

- **B-Store**
    - **Syntax:** `b!`
    - **Stack effect:** `b! ( value: i32 -- )`
    - **Description:** Store the top value of the data stack into register B.

- **A-Fetch**
    - **Syntax:** `a`
    - **Stack effect:** `a ( -- value: i32 )`
    - **Description:** Push the value of register A onto the data stack.

### Arithmetic Instructions

- **Add**
    - **Syntax:** `+`
    - **Stack effect:** `+ ( s: i32, t: i32 -- sum: i32 )`
    - **Description:** Add the top two values on the data stack.
    - **Operation (no EAM):** `dataStack.push(dataStack.pop() + dataStack.pop()), set carry flag`
    - **Operation (EAM):** `dataStack.push(dataStack.pop() + dataStack.pop() + carry), set carry flag`

- **Multiply Step**
    - **Syntax:** `+*`
    - **Stack effect:** `+* ( s: i32, t: i32 -- s: i32, t: i32 )`
    - **Description:** Perform a multiplication step.
    - **Operation:** `T <- T + (if A[0] then S else 0); A <- A >> 1; if T[0] then A[31] <- 1 else A[31] <- 0; T <- T >> 1`

- **Divide Step**
    - **Syntax:** `+/`
    - **Stack effect:** `+/ ( remainder: i32, quotient: i32 -- remainder: i32, quotient: i32 )`
    - **Description:** Perform one **restoring-division** micro-step.  
        - Dividend --`A`  
        - Divisor --`mem[B]`  
        - Partial remainder --`S`  
        - Partial quotient --`T`  
    - **Operation:**  
        1. `S <- S << 1`
        2. `if A[31] then S[0] <- 1`
        3. `A <- A << 1`
        4. `T <- T << 1`
        5. `if S >= mem[B] then`
            - `S <- S - mem[B]`
            - `T[0] <- 1`
    - [**Python example**](https://github.com/ryukzak/wrench/blob/master/example/step-by-step-div.py)

- **Left Shift**
    - **Syntax:** `2*`
    - **Stack effect:** `2* ( value: i32 -- shifted: i32 )`
    - **Description:** Shift the top value of the data stack left by one bit.

- **Right Shift**
    - **Syntax:** `2/`
    - **Stack effect:** `2/ ( value: i32 -- shifted: i32 )`
    - **Description:** Shift the top value of the data stack right by one bit, preserving the sign (Arithmetic shift).

- **Invert**
    - **Syntax:** `inv`
    - **Stack effect:** `inv ( value: i32 -- inverted: i32 )`
    - **Description:** Invert all bits of the top value on the data stack.

- **Extend Arithmetic Instructions**
    - **Syntax:** `eam`
    - **Stack effect:** `eam ( flag: i32 -- )`
    - **Description:** Pop value from the data stack and set EAM flag.

### Bitwise Instructions

- **And**
    - **Syntax:** `and`
    - **Stack effect:** `and ( s: i32, t: i32 -- bits: i32 )`
    - **Description:** Perform a bitwise AND on the top two values of the data stack.

- **Xor**
    - **Syntax:** `xor`
    - **Stack effect:** `xor ( s: i32, t: i32 -- bits: i32 )`
    - **Description:** Perform a bitwise XOR on the top two values of the data stack.

### Stack Manipulation Instructions

- **Drop**
    - **Syntax:** `drop`
    - **Stack effect:** `drop ( value: i32 -- )`
    - **Description:** Remove the top value from the data stack.

- **Dup**
    - **Syntax:** `dup`
    - **Stack effect:** `dup ( value: i32 -- value: i32, value: i32 )`
    - **Description:** Duplicate the top value of the data stack. One of the two instructions that do not clear the carry flag.

- **Over**
    - **Syntax:** `over`
    - **Stack effect:** `over ( s: i32, t: i32 -- s: i32, t: i32, s: i32 )`
    - **Description:** Copy the second value on the data stack to the top, pushing the data stack.

### Control Flow Instructions

- **Return**
    - **Syntax:** `;`
    - **Stack effect:** `; ( -- )`
    - **Description:** Return from a subroutine.
    - **Operation:** `p <- returnStack.pop()`

- **Call**
    - **Syntax:** `<label>`
    - **Stack effect:** `<address: i32> ( -- )`
    - **Description:** Call a subroutine at the specified label.
    - **Operation:** `returnStack.push(p + 5); p <- <label>`

- **Jump**
    - **Syntax:** `<label> ;`
    - **Stack effect:** `<address: i32> ; ( -- )`
    - **Description:** Jump to the specified label.
    - **Operation:** `p <- <label>`

- **Next**
    - **Syntax:** `next <label>`
    - **Stack effect:** `next <address: i32> ( -- )`
    - **Description:** Loop to the specified label, decrementing R.
    - **Operation:**
        - `if R != 0 then`
            - `R <- R - 1`
            - `p <- <label>`
        - `else returnStack.pop()`

- **If**
    - **Syntax:** `if <label>`
    - **Stack effect:** `if <address: i32> ( flag: i32 -- )`
    - **Description:** Jump to the specified label if the top value of the data stack is zero.
    - **Operation:** `if dataStack.pop() == 0 then p <- <label>`

- **Minus If**
    - **Syntax:** `-if <label>`
    - **Stack effect:** `-if <address: i32> ( value: i32 -- )`
    - **Description:** Jump to the specified label if the top value of the data stack is nonnegative.
    - **Operation:** `if dataStack.pop() >= 0 then p <- <label>`

- **Halt**
    - **Syntax:** `halt`
    - **Stack effect:** `halt ( -- )`
    - **Description:** Halt the machine.

### Register Manipulation Instructions

- **RIntoT**
    - **Syntax:** `r>`
    - **Stack effect:** `r> ( -- value: i32 )`
    - **Description:** Move the top value of the return stack to the data stack.

- **TIntoR**
    - **Syntax:** `>r`
    - **Stack effect:** `>r ( value: i32 -- )`
    - **Description:** Move the top value of the data stack to the return stack.
